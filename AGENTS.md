# AGENTS

## Project Overview

This repository contains `tba`, an async Rust 2024 client for The Blue
Alliance API v3. The package provides a library by default and an optional
`tba` command-line client. The default feature set is empty.

The public library surface is centered on:

- `APIClient`, re-exported from `src/api_client.rs`, for authentication,
  base-URL selection, HTTP GET requests, and optional client-side rate
  limiting.
- `APIResult<T>`, re-exported from `src/api_result.rs`, for successful data and
  its ETag, `304 Not Modified`, unauthorized responses, and other API errors.
- `tba::endpoints`, generated by the endpoint macro from declarations in
  `src/endpoints.rs`.
- `tba::models`, containing the serde models declared in `src/models.rs`.

## Repository Layout

- `src/lib.rs`: crate exports and feature-gated module wiring.
- `src/api_client.rs`: `reqwest` client construction, `X-TBA-Auth-Key`, the
  `X_TBA_AUTH_KEY` and `BASE_API_URL` environment variables, ETag request
  headers, and the optional Governor rate limiter.
- `src/api_result.rs`: conversion from `reqwest::Response` to `APIResult<T>`.
- `src/endpoints.rs`: the complete `endpoints!` declaration, grouped by TBA API
  domain/tag. It is also the source of CLI endpoint subcommands when the `cli`
  feature is enabled.
- `src/endpoints_macro.rs`: generation of async endpoint accessors and their
  feature-gated Clap command types.
- `src/models.rs`: generated serde model definitions. This is a single file;
  there is no `src/models/` module tree.
- `src/cli/`: CLI configuration, command definitions, output formatting,
  completion generation/installation, and command handlers.
- `src/main.rs`: entry point for the feature-gated `tba` binary.
- `.env.example`: example library environment configuration. Never commit a
  populated `.env` file or a real API key.

## Cargo Features

- `default`: no optional features.
- `rate-limit`: enables Governor-backed request throttling and
  `APIClient::with_rate_limiter`.
- `cli`: enables the `tba::cli` module and builds the `tba` binary. It includes
  Clap commands for endpoint requests, config management, and shell
  completions.

Code behind an optional feature must continue to compile both with that
feature enabled and with the default feature set. The binary cannot be built
without `cli` because its Cargo target has `required-features = ["cli"]`.

## Endpoint Conventions

Define and modify API coverage in the `endpoints!` block in
`src/endpoints.rs`; do not create a parallel hand-written endpoint layer. Each
entry supplies its documentation, relative path, typed input fields, and typed
output.

- Keep paths relative to `https://www.thebluealliance.com/api/v3`, beginning
  with `/`. Do not embed `/api/v3`, `/v3`, or the host in endpoint paths.
- Group endpoints under the existing API domains: `District`, `Event`,
  `Insight`, `MatchAPI`, `RegionalAdvancement`, `Search`, `TBA`, and `Team`.
- Use model types from `crate::models` for structured responses. Use
  `UnknownJsonObject` only when the upstream schema is intentionally dynamic or
  does not define a useful shape.
- Generated accessors take `&APIClient`, then their path parameters, followed
  by `Option<String>` for the ETag, and return `APIResult<T>`.
- Path parameters currently use their declared owned types, commonly `String`.
  Examples and callers must pass matching owned values.
- Preserve conditional-request support on every endpoint. The ETag remains the
  final accessor argument.
- Use an explicit `snake_case` override for names whose automatic conversion
  would be incorrect, especially acronyms such as `COPRs` and Rust keywords.
- Endpoint and field doc comments also populate CLI help. Keep them concise,
  accurate, and useful in both rustdoc and command help.

The macro's automatic case conversion is part of the current public API. In
particular, the library modules generated from `TBA` and `MatchAPI` are
`endpoints::t_b_a` and `endpoints::match_a_p_i`. Compile-check documented
paths instead of assuming how acronym-heavy identifiers expand. The CLI
normalizes generated command names to kebab case, such as `match-api`.

## Models

`src/models.rs` is marked as generated from the official TBA OpenAPI v3
specification. It includes season-specific score breakdowns, tagged and
untagged enums, shared API resources, and the `UnknownJsonObject` alias.

Prefer typed serde fields and preserve the exact wire names through serde
attributes. Avoid unrelated manual reshaping of generated types. No model
generation script is currently checked into this repository, so any spec sync
must be deliberate, reviewable, and tied to the upstream schema. Keep the
generated-file notice intact.

## Client and Result Behavior

- `APIClient::new()` reads the API key from `X_TBA_AUTH_KEY` and the optional
  base URL from `BASE_API_URL`.
- `APIClient::new_with(api_key, base_api_url)` gives explicit arguments
  precedence over environment values.
- The default base URL is
  `https://www.thebluealliance.com/api/v3`.
- A successful `APIResult::Ok` contains both the deserialized value and its
  ETag string. Callers may supply that ETag on a later request and handle
  `APIResult::NotModified`.
- Keep authentication material out of logs, fixtures, examples, and error
  output. Use placeholders in documentation and tests.

When changing response handling, account for every existing `APIResult`
variant and avoid introducing new panic paths for headers, remote response
bodies, or other untrusted input.

## CLI Conventions

The CLI is a supported optional interface, not a smoke-test binary. Its main
subcommands are `get`, `config`, `completions`, and `install-completions`.

- Endpoint commands are derived from the same `endpoints!` declaration as the
  library. Add endpoint-specific CLI behavior to the macro/declaration path
  rather than duplicating the endpoint list.
- The default config path is `~/.tbarc`; `--config` selects another file.
- CLI flags are merged with config values before `APIClient` falls back to
  environment variables. Preserve this behavior unless the task explicitly
  changes precedence.
- JSON and the three pretty-JSON variants are implemented. `jsonl`, `csv`, and
  `tsv` are declared output choices but currently return an unimplemented
  error; do not document them as working formats.
- Completion installation writes into shell-specific user configuration
  locations. Tests must redirect filesystem work to temporary paths and must
  not modify the developer's actual shell configuration.

## Style and Change Scope

- Use the repository's nightly rustfmt configuration in `.rustfmt.toml`. It
  enforces hard tabs, vertically laid-out imports, an 80-column width, and
  formatted strings/comments.
- Follow Rust 2024 idioms and the existing naming style.
- Keep public types and endpoint responses strongly typed.
- Add focused tests for behavior changes, including feature-gated tests when
  changing CLI or rate-limiter code.
- Do not make live authenticated API calls during routine tests. Prefer local
  response fixtures or a local test server for HTTP behavior.
- Preserve unrelated worktree changes and avoid broad refactors that are not
  required by the task.
- Never commit `.env` files, credentials, generated shell configuration, or
  other machine-local state.

## Validation

Run the checks relevant to the change. For a full handoff, use:

```sh
cargo +nightly fmt -- --check
cargo check
cargo test
cargo check --all-features
cargo test --all-features
cargo clippy --all-targets --all-features -- -D warnings
```

For CLI changes, also inspect the affected command surface, for example:

```sh
cargo run --features cli -- --help
cargo run --features cli -- get team simple --help
```

Do not make a live endpoint request merely to validate parsing or help output.
If a required command cannot run or fails for a pre-existing reason, report the
exact command and failure instead of silently skipping it.

## Documentation and Release Metadata

Keep `README.md` examples synchronized with the actual public module names,
owned argument types, feature flags, and CLI commands. Compile-check Rust
examples when public signatures change.

Before publishing, keep the version and package metadata in `Cargo.toml`, the
README installation guidance, and `LICENSE` aligned. The crate's declared
license is `LGPL-3.0-or-later`.
