# AGENTS

## Project Overview

This repository is a Rust 2024 Cargo workspace for The Blue Alliance API v3.
The workspace root is a virtual manifest and contains three packages:

- `tba` in `lib/`: the reusable asynchronous API client library.
- `tba-cli` in `cli/`: the command-line application whose installed binary is
  named `tba`.
- `codegen` in `codegen/`: a non-published generator for checked-in Rust
  source derived from the pinned OpenAPI document.

The library's default feature set is empty. The CLI is a separate package that
depends on the library with its `cli` and `rate-limit` features enabled.

The public library surface is centered on:

- `APIClient`, re-exported from `lib/src/api_client.rs`, for authentication,
  base-URL selection, HTTP GET requests, and optional client-side rate
  limiting.
- `APIResult<T>`, re-exported from `lib/src/api_result.rs`, for successful data
  and its ETag, `304 Not Modified`, unauthorized responses, response decode
  errors, and other API errors.
- `tba::endpoints`, generated by the endpoint macro from declarations in
  `lib/src/endpoints.rs`.
- `tba::models`, containing the serde models declared in
  `lib/src/models.rs`.

## Workspace Layout

- `Cargo.toml`: virtual workspace manifest and shared dependency versions.
- `Cargo.lock`: lockfile shared by all workspace packages.
- `codegen.toml`: generator input path and expected OpenAPI/TBA API versions.
- `codegen/`: source and tests for the non-published `codegen` package.
- `lib/Cargo.toml`: manifest for the published `tba` library package.
- `lib/src/lib.rs`: library exports and module wiring.
- `lib/src/api_client.rs`: Reqwest client construction, authentication,
  base-URL selection, ETag request headers, and optional Governor rate
  limiting.
- `lib/src/api_result.rs`: conversion from `reqwest::Response` to
  `APIResult<T>` and successful-response decode diagnostics.
- `lib/src/endpoints.rs`: the complete `endpoints!` declaration, grouped by
  TBA API domain/tag.
- `lib/src/models.rs`: model module root, generated-model re-exports, and the
  few endpoint-only compatibility types absent from the component schemas.
- `lib/src/models/generated.rs`: checked-in output owned by `codegen`; do
  not edit it directly.
- `lib/src/models/media.rs` and `lib/src/models/insight_v2.rs`: focused manual
  serde implementations for discriminator-sensitive schema families.
- `lib/src/util/`: internal endpoint-macro support and response-body excerpt
  formatting.
- `lib/tests/`: library integration tests and versioned API fixtures.
- `cli/Cargo.toml`: manifest for the `tba-cli` package and `tba` binary.
- `cli/src/main.rs`: CLI crate root and process entry point.
- `cli/src/commands/`: top-level Clap command and subcommand definitions.
- `cli/src/handlers/`: configuration, endpoint, output, and completion command
  handlers.
- `cli/src/config.rs`: CLI configuration-file loading, writing, and setting
  precedence.
- `cli/src/output_format.rs`: CLI output-format selection.
- `cli/src/util/`: shell detection, completion generation, and filesystem
  helpers.
- `tba_api_v3_16_0.openapi.json`: checked-in upstream OpenAPI document;
  its `info.version` identifies TBA API version `3.16.0`.
- `review/`: review task descriptions. Preserve unrelated task files.
- `.env.example`: example environment configuration. Never commit a populated
  `.env` file or a real API key.

## Workspace and Cargo Conventions

Run Cargo commands from the workspace root and select a package explicitly
when the distinction matters:

```sh
cargo check -p tba
cargo test -p tba
cargo run -p tba-cli -- --help
```

The package names are `tba`, `tba-cli`, and `codegen`; `cli`, `codegen`,
and `lib` are directory names, not Cargo package names. The `tba-cli` package
produces a binary named `tba`.

Keep shared dependency versions in the root `[workspace.dependencies]` table
and use `workspace = true` from member manifests when practical. The CLI may
depend on the library, but the library must not depend on the CLI package.

The `tba` and `tba-cli` packages are independently publishable. Keep their
versions and the `tba-cli` dependency on `tba` synchronized when preparing a
release. `codegen` is marked `publish = false`.

## Library Features

The `tba` package currently defines:

- `default`: no optional features.
- `rate-limit`: enables Governor-backed request throttling and
  `APIClient::with_rate_limiter`.
- `cli`: enables Clap command types currently emitted alongside endpoint
  accessors for consumption by `tba-cli`.

Code behind optional features must continue to compile both with that feature
enabled and with `--no-default-features`. Do not add CLI-only dependencies to
the library's default feature set.

## Endpoint Conventions

Define and modify API coverage in the `endpoints!` block in
`lib/src/endpoints.rs`; do not create a parallel hand-written endpoint list.
Each entry supplies its documentation, relative path, typed input fields, and
typed output.

- Keep paths relative to
  `https://www.thebluealliance.com/api/v3`, beginning with `/`. Do not embed
  `/api/v3`, `/v3`, or the host in endpoint paths.
- Group endpoints under the existing API domains: `District`, `Event`,
  `Insight`, `MatchAPI`, `RegionalAdvancement`, `Search`, `TBA`, and `Team`.
- Use model types from `crate::models` for structured responses. Use
  `UnknownJsonObject` only when the upstream schema is intentionally dynamic or
  does not define a useful shape.
- Generated accessors take `&APIClient`, then their path parameters, followed
  by `Option<String>` for the ETag, and return `APIResult<T>`.
- Path parameters currently use their declared owned types, commonly `String`.
  Examples and callers must pass matching owned values.
- Preserve conditional-request support on every endpoint. The ETag remains the
  final accessor argument.
- Use an explicit `snake_case` override for names whose automatic conversion
  would be incorrect, especially acronyms such as `COPRs` and Rust keywords.
- Endpoint and field doc comments currently also populate CLI help. Keep them
  concise, accurate, and useful in both contexts.

The macro's automatic case conversion is part of the current public API. In
particular, the library modules generated from `TBA` and `MatchAPI` are
`endpoints::t_b_a` and `endpoints::match_a_p_i`. Compile-check documented paths
instead of assuming how acronym-heavy identifiers expand. The CLI normalizes
generated command names to kebab case, such as `match-api`.

The current endpoint macro also emits feature-gated Clap types and JSON
dispatch used by `tba-cli`. Until that generation is deliberately decoupled,
changes to endpoint metadata must be tested against both the library accessor
and CLI command surfaces.

## Models and OpenAPI

`lib/src/models/generated.rs` represents every ordinary component schema from
the checked-in TBA OpenAPI document, including objects, nested definitions,
collections, nullable fields, aliases, enums, and shape-based unions. The
module root re-exports those definitions alongside the small set of manual
discriminator-sensitive models.

Regenerate or verify generator-owned source with:

```sh
cargo run -p codegen -- generate
cargo run -p codegen -- check
```

The workspace-root `codegen.toml` selects the specification and expected
OpenAPI and TBA API versions and contains Rust compatibility overrides under
its `overrides` table. Overrides must fail when stale or unused. The generator
uses `x-enum-varnames` when present and derives other string-enum names from
their wire values. Generated integer enums retain unknown wire values for
forward compatibility. Extend generator coverage incrementally, and fail
clearly on unsupported schema constructs rather than silently weakening types.

Each generated model family owns its schema parsing and `quote`-based token
rendering. Keep cross-model dispatch and validation in the orchestration layer.
Generated tokens are validated with `syn`, normalized with Prettyplease, and
formatted with nightly rustfmt; preserve that pipeline as coverage expands.

Manual model modules contain intentional corrections where shape-only serde
derivation is insufficient. In particular:

- `Media` uses discriminator-aware serialization and deserialization.
- Insight leaderboard contexts use marker-aware deserialization.
- The team-event simple-matches endpoint returns `Vec<MatchSimple>` despite an
  incorrect upstream response schema.

Preserve these behaviors and their fixture tests during schema updates. Prefer
typed serde fields, exact wire names, and deliberate handling of nullability,
unknown enum values, and additional upstream object fields. Avoid unrelated
manual reshaping of generated types.

Tie model or endpoint changes to the checked-in OpenAPI version or to a
documented override. Do not fetch or replace the pinned specification as an
incidental part of another task.

## Client and Result Behavior

- `APIClient::new()` reads the API key from `X_TBA_AUTH_KEY` and the optional
  base URL from `BASE_API_URL`.
- `APIClient::new_with(api_key, base_api_url)` gives explicit arguments
  precedence over environment values.
- The default base URL is
  `https://www.thebluealliance.com/api/v3`.
- A successful `APIResult::Ok` contains both the deserialized value and its
  ETag string. Callers may supply that ETag on a later request and handle
  `APIResult::NotModified`.
- Successful responses that cannot be decoded produce
  `APIResult::DecodeError` with sanitized request context and a bounded,
  readable body excerpt.
- Keep authentication material out of logs, fixtures, examples, and error
  output. Use placeholders in documentation and tests.

When changing response handling, account for every `APIResult` variant and
avoid introducing panic paths for headers, URLs, response bodies, or other
untrusted input.

## CLI Conventions

The `tba-cli` package is a supported application, not a smoke-test binary. Its
main subcommands are `get`, `config`, `completions`, and
`install-completions`.

- The executable name is `tba`, even though the Cargo package is `tba-cli`.
- Endpoint commands currently use `tba::endpoints::GetSubcommand`, generated by
  the library's `cli` feature. Do not duplicate endpoint paths or response
  types in the CLI by hand.
- The default config path is `~/.tbarc`; `--config` selects another file.
- CLI settings resolve command-line flags first, environment variables second,
  config-file values third, and built-in defaults last.
- JSON and the three pretty-JSON variants are implemented. `jsonl`, `csv`, and
  `tsv` are declared choices but currently return an unimplemented error; do
  not document them as working formats.
- Completion installation writes into shell-specific user configuration
  locations. Tests must redirect filesystem work to temporary paths and must
  not modify the developer's actual shell configuration.
- Commands that fail must print an error and exit nonzero.

## Style and Change Scope

- Follow the root `.rustfmt.toml`: hard tabs, an 80-column width, Unix newlines,
  and reordered imports.
- Follow Rust 2024 idioms and the existing naming style.
- Keep public types and endpoint responses strongly typed.
- Add focused tests in the affected package. Put library fixtures under
  `lib/tests/fixtures/` and avoid coupling CLI tests to a developer's home
  directory or shell configuration.
- Do not make live authenticated API calls during routine tests. Prefer local
  response fixtures or a loopback test server for HTTP behavior.
- Preserve unrelated worktree and index changes, including untracked review
  tasks and staged files.
- Avoid broad refactors outside the requested package or architectural seam.
- Never commit `.env` files, credentials, generated shell configuration, or
  other machine-local state.

## Validation

Run checks relevant to the changed package. For a full workspace handoff, use:

```sh
cargo fmt --all -- --check
cargo check -p tba --no-default-features
cargo test -p tba --no-default-features
cargo check -p tba --all-features
cargo test -p tba --all-features
cargo check -p tba-cli
cargo test -p tba-cli
cargo test -p codegen
cargo run -p codegen -- check
cargo check --workspace --all-features
cargo test --workspace --all-features
cargo clippy --workspace --all-targets --all-features -- -D warnings
```

For CLI changes, also inspect the affected command surface, for example:

```sh
cargo run -p tba-cli -- --help
cargo run -p tba-cli -- get team simple --help
```

Do not make a live endpoint request merely to validate parsing or help output.
If a required command cannot run or fails for a pre-existing reason, report
the exact command and failure instead of silently skipping it.

## Documentation and Release Metadata

Keep `README.md` examples synchronized with package names, public module names,
owned argument types, feature flags, and CLI commands. Compile-check Rust
examples when public signatures change.

The workspace packages have separate manifests and publication metadata.
Before publishing, keep both package versions, the CLI's `tba` dependency,
README installation guidance, and `LICENSE` aligned. Both packages declare
`LGPL-3.0-or-later`.
